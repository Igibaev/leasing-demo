# Как провести показ: подготовка, структура, слова ведущего

Этот файл — руководство ведущего. Сами слайды и заметки к ним — в [slides/](slides/README.md); технический маршрут и критерии приёмки — в [DEMO_SCENARIO.md](DEMO_SCENARIO.md); ограничения — в [../ASSUMPTIONS.md](../ASSUMPTIONS.md).

Формат, на который рассчитан материал: 20 минут — 5 минут слайдов, 11–12 минут живого показа, 3–4 минуты вопросов. Один ведущий, ноутбук, Chromium, локальный сервер, интернет не нужен.

---

## 0. Главное правило

Это **прототип на синтетических данных**. AML, ЭЦП и банковская выписка — обозначенные имитации. Ни одна цифра в демо не является утверждением о действующих налоговых правилах или о фактической экономии времени. Если прозвучит вопрос «это уже работает с банком?» — ответ «нет, это имитация, реальная интеграция в объём прототипа не входила».

Нарушение этого правила обесценит весь показ быстрее, чем любая техническая ошибка.

## 1. Подготовка (за 30 минут до показа)

```bash
cd leasing-demo
npm ci
npm run db:setup        # создаст и засеет prisma/dev.db, существующие данные не тронет
npm run build
npm start               # http://127.0.0.1:3000
```

Чек-лист перед аудиторией:

- [ ] В шапке видна системная дата **21.09.2026**. Если нет — база не в исходном состоянии, сделать сброс (см. ниже).
- [ ] Выбрана роль **Айдар Сатпаев — Менеджер по продажам**.
- [ ] Открыта одна вкладка, масштаб 100%, ширина окна не меньше ~1440 px.
- [ ] Закрыты уведомления ОС, мессенджеры, почта.
- [ ] Открыт `demo/slides/deck.html` в отдельном окне, на титульном слайде подставлены дата и имя.
- [ ] Рядом открыт этот файл или распечатан раздел 3.
- [ ] Прогнан «сухой» проход сценария целиком — минимум один раз, накануне.

**Сброс к исходному состоянию** (удаляет содержимое локальной демо-базы; если нужны результаты прошлого прогона — сначала скопировать `prisma/dev.db`):

```bash
npm run db:reset -- --confirm-demo-reset
npm start
```

После сброса старые вкладки со случайными ID дают 404 — вернуться на главную и выбрать роль заново.

## 2. Слайды (5 минут, 5 слайдов)

Готовый дек лежит в [`slides/`](slides/README.md). Для показа достаточно одного файла **`demo/slides/deck.html`** — он самодостаточный, интернет не нужен, открывается двойным щелчком.

Управление: `←` `→` `Space` — слайды, `Home` / `End` — в начало и конец, **`N` — заметки докладчика под слайдом**, `F` — полный экран. PDF — печать из браузера (альбомная, поля нулевые, фоновая графика включена).

Заметки к каждому слайду уже написаны — перед показом прочитайте их с клавишей `N`. Ниже — что на слайдах и на чём делать акцент.

| # | Слайд | Содержание | Главное вслух |
|---|---|---|---|
| 1 | Титул | «АИС Лизинг — прототип рабочего места», плейсхолдеры `[ДАТА ПОКАЗА]` и `[ИМЯ ВЕДУЩЕГО]` — **подставьте свои** | «Прототип на синтетических данных. Пять слайдов за пять минут, дальше — само приложение» |
| 2 | Проблема | Три боли против трёх принципов ТЗ (раздел 40): одно досье, один сквозной процесс, один аудиторский след | Цифр не приводим — ничего не замеряли |
| 3 | Что показываем | Одна сделка, три сценария, привязка к ТЗ §5–7, §13–16, §21–22 | «Это часть контура, а не весь ТЗ: CRM, скоринг, лимиты, ковенанты, взыскание в прототип не входили» |
| 4 | Схема процесса | Цепочка: заявка → 5 согласований по очереди → комитет → договор → платежи → просрочка | «Активен ровно один шаг, перескочить нельзя». Оговорка: маршрут задан в коде, а ТЗ требует настройки администратором — этого нет. Правило «2 из 3» — демонстрационное |
| 5 | Настоящее и имитация | Две колонки со ссылками на разделы ТЗ. **Самый важный слайд** | «Имитация — экран есть, внешней системы за ним нет». Если спросят про банк: «нет, реальная интеграция в объём не входила» |

**Отдельного слайда «Границы» в деке нет** — это сделано намеренно, чтобы уложиться в пять минут. Сразу после пятого слайда проговорите границы **вслух**, одной фразой, и уходите в приложение:

> «Коротко о границах: это не production — нет входа и разграничения доступа, запуск локальный, данные синтетические, налоговые параметры учебные. Дальше — живой показ».

Если что-то правите в слайдах (`.dc.html` или `canvas.json`), пересоберите единый файл:

```bash
node demo/slides/build-deck.mjs
```

## 3. Живой показ — по шагам

Формат: **что нажать → что должно появиться → что сказать**. Если «должно появиться» не совпало — остановитесь и смотрите раздел 4, не идите дальше.

Роль переключается выпадающим списком **справа вверху** (подпись «Демо-пользователь», формат «Имя — Роль»). Набор пунктов меню меняется вместе с ролью — это само по себе стоит показать вслух. Переключение роли **сохраняет текущий адрес**, поэтому карточка заявки остаётся открытой.

### Блок 1. Досье и заявка — 2 минуты

**Роль: Айдар Сатпаев — Менеджер по продажам.** Меню: Дашборд · Клиенты · Заявки · Калькулятор · Договоры · Личный кабинет.

| # | Действие | Что должно появиться | Что сказать |
|---|---|---|---|
| 1.1 | Меню → **«Клиенты»** | Список клиентов, поле фильтра «Фильтр: наименование, БИН/ИИН, ОКЭД» | «Роль определяет, какие разделы вообще видны» |
| 1.2 | В фильтр ввести `ДЕМО` → «Найти» | В списке **ТОО ДЕМО — Учебная логистика**, БИН `000000000001` | «Данные учебные, БИН намеренно не настоящий» |
| 1.3 | Кликнуть по названию клиента | Досье: рейтинг, EWS, финансовые показатели, история проверок | «Сюда стекается всё, что известно о клиенте» |
| 1.4 | Меню → **«Заявки»** → кнопка **«+ Новая заявка»** | Форма из 7 полей | — |
| 1.5 | Заполнить форму (см. ниже) | — | Проговаривайте суммы вслух, пока набираете |
| 1.6 | Кнопка **«Создать заявку (черновик)»** | Откроется карточка заявки `Z-2026-…` | «Ничего не пересчитывали руками» |

**Значения формы (шаг 1.5):**

| Поле | Значение |
|---|---|
| Клиент | ТОО ДЕМО — Учебная логистика · 000000000001 |
| Продукт (предмет лизинга) | Грузовой транспорт |
| Стоимость предмета, ₸ | `60000000` |
| Первоначальный взнос, ₸ | `12000000` |
| Срок, мес. | 12 мес. |
| Годовая ставка, % | `18` |
| Тип графика | Аннуитет |

**Шаг 1.7 — показать карточку.** Ведите пальцем сверху вниз, 3–4 остановки, не больше:

1. Заголовок: номер заявки, статус **«Черновик»**, продукт. В строке под ним — **«финансируем не более 48 000 000 ₸»**.
2. Блок **«Оценка риска (автоматический скоринг)»**: балл **76.25**, рейтинг **B**, стоп-факторов задето **0**, маршрут **STD**.
3. Блок **«Стоп-факторы и лимиты»**: лимит на клиента и лимит по отрасли — «в норме».
4. Блок **«График платежей · 12 периодов»**, подпись «расчёт ядром decimal.js: фактические дни, база 365, НДС 12%». Под таблицей — **IRR 23.91%**.

> Сказать: «График, скоринг и маршрут посчитаны в момент создания. Дальше эта заявка поедет по людям».

**Шаг 1.8 — отправка.** Блок **«Действия»** → кнопка **«Отправить на рассмотрение»**.

Что должно появиться:
- Синее уведомление **«Заявка передана на согласование»** вверху.
- Статус сменился на **«Зарегистрирована»**.
- Появился блок **«Маршрут согласования»** — подпись «стандартный маршрут», **6 шагов**.
- Шаг 1 «Анализ кредитной заявки» подсвечен и в работе, шаги 2–6 — **«Ожидает предыдущий шаг»**.

> Ключевая фраза блока: **«Активен ровно один шаг. Перескочить через людей нельзя — это проверяется на сервере, а не кнопкой в интерфейсе»**.

*Экономия времени:* если опаздываете — пропустите 1.4–1.6 и работайте с готовым черновиком `Z-DEMO-001` из списка заявок, прямо сказав, что это подготовленные данные.

### Блок 2. Согласование и договор — 5–6 минут

Вы остаётесь на карточке заявки. Для каждой роли повторяется один и тот же цикл из трёх действий.

**Цикл согласования (повторить 5 раз):**

1. Справа вверху выбрать следующего пользователя из таблицы ниже.
2. Страница перезагрузится, **адрес заявки сохранится**. Внизу карточки появится блок с названием текущего шага и подписью «Ваша роль: …».
3. Нажать зелёную кнопку **«Согласовать»**. Появится уведомление **«Решение по шагу сохранено.»**, в маршруте загорится следующий шаг.

| # | Шаг маршрута | Кого выбрать |
|---|---|---|
| 1 | Анализ кредитной заявки | **Динара Ахметова — Кредитный аналитик** |
| 2 | Маркетинговое заключение | **Марат Жумабаев — Руководитель продаж** |
| 3 | Юридическое заключение | **Зауреш Бектанова — Юрист** |
| 4 | Профиль риска | **Алия Нурпеисова — Риск-менеджер** |
| 5 | Проверка ПОД/ФТ | **Нурлан Оспанов — ПОД/ФТ** |

Темп: на шагах 1–2 показывайте подробно, на 3–5 ускоряйтесь — идея уже считана.

Что сказать по ходу (по одной фразе, не всё сразу):
- На шаге 1: «Обратите внимание на подпись — *создатель заявки не согласует собственный объект*. Это Maker-Checker».
- На шаге 2: «Рядом с кнопкой есть поле комментария. Для отклонения комментарий обязателен».
- На шаге 4: «Стоп-факторы проверяются заново на каждом решении. HARD блокирует сделку без вариантов, SOFT требует письменного обоснования руководителя рисков».

После пятого согласования шаг 6 «Заседание кредитного комитета» становится активным.

**Шаг 2.6 — первый голос.** После пятого согласования статус заявки в заголовке становится **«Комитет»**, а на карточке появляется отдельный блок: «Ожидается решение демо-комитета: два голоса "за" из трёх».

Выбрать **Дамир Султанов — Член кредитного комитета**. В этом блоке появится ссылка **«Перейти к голосованию»** → нажать.

*Под другой ролью вместо ссылки будет подсказка «Выберите роль "Член кредитного комитета", "Руководство" или "Руководитель продаж"» — её тоже можно показать, это наглядно про права.*

Что должно появиться: страница **«Решение кредитного комитета»**, блок «Повестки открытых демо-заседаний», в таблице — строка с вашим номером заявки и кнопки **«За»** / **«Против»**.

Нажать **«За»**.

Что должно появиться: **«Ваш голос уже учтён»**, строка **осталась** в повестке, заявка **не одобрена**.

> «Одного голоса недостаточно. В этом и смысл коллегиального решения».

**Шаг 2.7 — второй голос.** Выбрать **Тимур Карибаев — Руководство** (вторая роль с правом голоса) → в той же строке нажать **«За»**.

Что должно появиться: строка **исчезла** из повестки. Если вернуться на карточку заявки, статус — **«Одобрена»**.

> «Правило "два голоса из трёх" — демонстрационное, реальный регламент комитета не согласован».

**Шаг 2.8 — договор.** Выбрать **Арман Тлеубаев — Лизинговые операции**. Меню: Дашборд · Клиенты · Договоры · Платежи · Мониторинг.

Меню → **«Договоры»** → перейти к формированию договора. Заголовок страницы — **«Формирование договора»**, блок **«Выберите согласованную заявку»**.

Найти свою заявку → ссылка **«Выбрать»** → появится карточка заявки с кнопкой **«Сформировать договор»** → нажать.

Что должно появиться:
- Уведомление **«Договор сформирован»**.
- Карточка договора **ДЛ-2026-…**, бейдж **«Действует»**, бейдж **«1. версия графика»**.
- Зелёная плашка **«Просрочки нет»**.
- **«График платежей · 12 периодов»**.
- Справа блок **«Актив»**: тип VEHICLE, наименование, VIN, стоимость 60 000 000 ₸, статус ORDERED.

> «Договор, график и предмет лизинга создаются одной транзакцией. Половинчатого состояния — договор есть, графика нет — не бывает».

**Шаг 2.9 — ЭЦП (необязательный, 15 секунд).** Справа блок **«Электронная подпись»** с подписью «мок: в продукте — НУЦ РК (GOST)». Можно нажать **«Подписать ЭЦП»**, но **обязательно** с оговоркой:

> «Это имитация. Никуда ничего не уходит — фиксируется только запись в журнале аудита. В продукте здесь интеграция с НУЦ РК».

### Блок 3. Платёж и просрочка — 3–4 минуты

**Роль: Куаныш Сериков — Бухгалтерия.** Меню: Дашборд · Договоры · Платежи · BI-дашборды.

| # | Действие | Что должно появиться |
|---|---|---|
| 3.1 | Меню → **«Договоры»** → открыть **ДЛ-DEMO-001** | Карточка договора, красная плашка **«Просрочка: DPD 31 · 31–60 дней»** |
| 3.2 | Справа блок **«Принять платёж»**, в поле «Сумма, ₸» ввести `1000` → **«Зачислить»** | Уведомление **«Платёж зачислен»**, поле очищено, внизу в «Истории платежей» строка **1 000 ₸ · MANUAL** |

> Скажите прямо на шаге 3.1: «Это подготовленный договор с историей, чтобы не ждать реального времени».
>
> На шаге 3.2 прочитайте подпись под кнопкой вслух: «Аллокация по приоритету: пени → комиссия → НДС → проценты → основной долг, с учётом ранее внесённых сумм».

**Шаг 3.3 — импорт выписки.** Меню → **«Платежи»**. Заголовок **«Платежи и выписки»**, блок «Журнал платежей».

Нажать **«Импортировать демо-выписку»**.

Что должно появиться: уведомление **«Импортировано: 2, зачислено по графикам: 2, ранее учтено: 0»**, в журнале две новые строки с бейджем **«выписка»**.

> «Банк не подключён. Читается подготовленный файл `mocks/bank-statement.csv`: две операции, 10 000 и 15 000 тенге, обе с номером договора ДЛ-DEMO-001 и валютой KZT. Строка зачисляется только при точном совпадении договора и валюты — на случайный договор деньги не попадут».

**Шаг 3.4 — повторный импорт. Не пропускайте этот шаг.** Нажать **ту же кнопку ещё раз**.

Что должно появиться: **«Импортировано: 0, зачислено по графикам: 0, ранее учтено: 2»**. Новых строк в журнале нет.

> «Повторная загрузка того же файла не задваивает платежи — каждая операция помечена своим идентификатором. Для бухгалтерии это обычно самый больной вопрос».

**Шаг 3.5 — вернуться в договор.** Меню → «Договоры» → **ДЛ-DEMO-001**.

Что должно появиться:
- В графике **первая строка**: дата 21.08.2026, платёж 75 371,61 ₸, **оплачено 26 000 ₸**, статус **PARTIAL**.
- Красная плашка просрочки **осталась**.
- В «Истории платежей (аллокации)» — три записи: 1 000 MANUAL, 10 000 BANK, 15 000 BANK.

> «Частично оплаченный период не исчезает из просрочки. Остаток считается с комиссией и НДС, а не только по телу долга».

*Если колонка «Статус» ушла за правый край:* таблица прокручивается по горизонтали — либо прокрутите, либо опирайтесь на красную плашку сверху, там те же цифры.

**Шаг 3.6 — перемотка времени.** Выбрать **Руслан Айтмуханов — Системный администратор** (у него самое широкое меню, включая «Просрочка», «Аудит» и «Администрирование»).

Меню → **«Администрирование»** → блок **«Симуляция времени»** (подпись «системная дата сейчас: 21.09.2026»).

В списке **«Сдвинуть время на»** выбрать **«30 дней (месяц)»** → кнопка **«Симулировать время»**.

Что должно появиться: уведомление **«Системная дата обновлена.»**, в шапке справа дата сменилась на **21.10.2026**.

**Шаг 3.7 — результат.** Меню → **«Просрочка»**.

Что должно появиться: страница **«Мониторинг просрочки»**, реестр с колонками Договор / Клиент / Ближайший платёж / DPD / Бакет / Просрочено. Найти строку **ДЛ-DEMO-001** — **DPD 61**, бакет **61–90 дней**.

Открыть договор ссылкой «Открыть →».

Что должно появиться: плашка **«Просрочка: DPD 61 · 61–90 дней»**, неоплаченная основная часть 111 419,75 ₸, проценты 11 295,85 ₸, подпись «Пересчитывается от системной даты, которая сейчас 21.10.2026».

> «61 день — не случайное число. Первый непогашенный период приходится на 21 августа, внесённых 26 000 тенге не хватает на платёж 75 371,61, поэтому просрочка считается от 21 августа. Сдвинули дату на месяц — было 31 день, стало 61».

**Шаг 3.8 — финал.** Меню → **«Аудит»**. Заголовок «Журнал аудита», колонки Время / Пользователь / Роль / Объект / Операция / Старое / Новое.

Показать записи: создание заявки, согласования по ролям, решение комитета, платежи, перемотка времени.

## 4. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Страница отдала 404 после сброса базы | Вернуться на главную, выбрать роль заново — ID объектов пересоздались |
| Кнопки «Согласовать» нет | Выбрана не та роль, либо шаг уже пройден. Проверьте подсвеченный шаг маршрута |
| Заявка не одобряется после двух голосов | Голосовали одним и тем же пользователем. Нужны два разных члена комитета |
| Импорт дал 0 с первого раза | Выписка уже импортирована в этом прогоне. Так и скажите: «это и есть защита от дублей» |
| DPD не 61 | Сдвиг времени был не на 30 дней или база не в исходном состоянии |
| Сервер не поднялся | **Не выдавайте статичные картинки за работающую систему.** Покажите снимки из `.demo-artifacts/`, скажите, что это записи реального прогона, и признайте, что живое демо не состоялось |

## 5. Ответы на вероятные вопросы

**«Это можно ставить в работу?»** Нет. Нет аутентификации, разграничения доступа клиентских данных и сертификации расчётов. Это прототип процесса.

**«Расчёты правильные?»** Арифметика выполнена аккуратно (decimal.js, фактические дни, база 365), но формулы, НДС 12% и комиссия — учебные параметры. Их нужно подтвердить с владельцем процесса.

**«Сколько времени это экономит?»** Не измерялось. Прототип показывает прослеживаемость, а не эффект.

**«Почему все роли доступны одним переключателем?»** Это приём показа, чтобы за 10 минут пройти маршрут одним человеком. В продукте — обычный вход и права.

**«Данные настоящие?»** Нет, полностью синтетические: БИН `000000000001`, адреса `example.invalid`, телефоны нерабочие.

**«Сколько заняла разработка / что дальше?»** Следующие шаги перечислены в ASSUMPTIONS.md, раздел «После демо»: подтверждение формул и регламента, аутентификация и права, реальные интеграции, тесты конкурентной записи.
