# АИС Лизинг — локальное демо

Прототип рабочего места сотрудников лизинговой компании: заявка и расчёт графика → согласование по ролям → решение комитета → договор → платежи и контроль просрочки.

Next.js 15 / React 19 / TypeScript, Prisma 6 / SQLite, Tailwind. Не production-система. Переключатель пользователей открыт специально для демонстрации; реальные данные вводить не следует.

**Статус передачи:** серверные проверки и сборка проходят; браузерный прогон пока выявляет ошибки гидратации и гонку в тесте навигации. Демо ещё не признано полностью готовым. Подробности и следующий шаг — в [HANDOFF.md](HANDOFF.md).

## Запуск с чистого checkout

Нужны Node.js 22 или 24, npm и интернет для первой установки. Секреты, `.env`, Docker, банковский доступ не нужны.

```bash
git clone --branch main https://github.com/Igibaev/leasing-demo.git
cd leasing-demo
npm ci
npm run db:setup
npm run build
npm start
```

Открыть http://127.0.0.1:3000. В шапке выбрать «Айдар Сатпаев — Менеджер по продажам». Для разработки — `npm run dev`.

`db:setup` применяет миграции и заполняет пустую базу. Существующие данные не сбрасывает. SQLite хранится в `prisma/dev.db`. Запуск привязан к loopback; публичное размещение этого прототипа не входит в демо.

## Показ

Подробный маршрут, роли, ожидаемые результаты и запасной план: [demo/DEMO_SCENARIO.md](demo/DEMO_SCENARIO.md).

Опорные данные после подготовки базы:

- клиент «ТОО ДЕМО — Учебная логистика», фиктивный БИН `000000000001`;
- черновик `Z-DEMO-001`: 60 млн ₸, взнос 12 млн, 12 месяцев, 18%;
- отдельный договор `ДЛ-DEMO-001` для платежей и просрочки;
- `mocks/bank-statement.csv`: две демонстрационные операции по этому договору, всего 25 000 ₸;
- системная дата 21.09.2026; 41 клиент, 62 заявки, 36 договоров, 19 пользователей.

Имена и реквизиты сгенерированы для прототипа. Учебный БИН намеренно не является реальным идентификатором. ЭЦП, AML и документы — явно обозначенные имитации. НДС 12% и комиссия 0,6% от стоимости за весь срок — учебные параметры, не утверждение о действующих налоговых правилах.

## Повторный показ

Остановить сервер. Если нужно сохранить текущие результаты, сначала скопировать `prisma/dev.db` в безопасное место. Следующая команда **удаляет содержимое локальной демо-базы**:

```bash
npm run db:reset -- --confirm-demo-reset
npm start
```

Сброс возвращает исходные данные и дату. Сборку повторять после изменения кода; после одного сброса данных она не требуется. Тесты серверных сценариев работают в отдельной временной базе и не меняют `dev.db`.

## Проверки

```bash
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run build
```

Браузерный прогон production-сборки (сам создаёт временную базу и запускает сервер):

```bash
npx playwright install chromium
npm run test:browser
```

`test:e2e` проверяет реальные серверные действия и SQLite, но подменяет API Next для cookie/redirect. `test:browser` проверяет интерфейс и настоящие HTTP Server Actions. Скриншоты сохраняются в `.demo-artifacts/`.

## Границы демо

[ASSUMPTIONS.md](ASSUMPTIONS.md) описывает допущения и отложенные работы. [HANDOFF.md](HANDOFF.md) содержит состояние работы и фактические проверки.

- Комитет: ROLE-02, ROLE-14, ROLE-15; два голоса «за» — одобрение, два «против» или отсутствие большинства после трёх голосов — отказ. Это демонстрационное правило.
- Согласование строго последовательно; HARD блокирует сделку; SOFT требует обоснования ROLE-05 перед переходом с расширенного контроля.
- Банк не подключён: кнопка читает только подготовленный CSV, сопоставляет точный номер договора и KZT, повторные externalId пропускает.
- Ручные платежи доступны бухгалтерии/администратору, учитывают предыдущие оплаты, не принимают превышение остатка. Сохранение платежа, распределения и аудита атомарно.
- Нет полноценной аутентификации, клиентской изоляции, реального документооборота, налоговой сертификации или многопользовательской промышленной эксплуатации.
