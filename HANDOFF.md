# HANDOFF — leasing-demo

## Цель и ветка

Довести до воспроизводимого локального демо три сценария: досье/заявка, согласование/договор, платёж/просрочка. Работа в `main`, исходный коммит `48d515e14b74f49a79ed56581594f2ce9ea79a0a`. Репозиторных AGENTS.md не найдено. Аудитория и срок пользователем не уточнены; рабочее допущение — один демонстратор, ноутбук/Chromium, 10–12 минут.

## Что изменено

- Последовательный маршрут: только первый шаг PENDING, последующие WAITING; запрет перескока, повторного решения и возобновления отклонённой заявки. Отправка и решение шага выполняются транзакционно.
- HARD действительно блокирует сделку; override только для сработавшего SOFT и с обоснованием; расширенный контроль требует устранения SOFT.
- Создаётся повестка новой заявки; три роли голосуют, большинство завершает заявку, повторный голос запрещён. Прямое согласование вместо голосования закрыто.
- Договор, график и предмет создаются одной транзакцией. Номера заявок/договоров получили случайный UUID-суффикс вместо диапазона из 900 значений.
- Оплаты учитывают частично погашенные компоненты; переплата/неверная сумма отклоняются; запись и распределение атомарны. Повтор запроса формы идемпотентен по requestId.
- CSV содержит точный договор/валюту; нет зачисления на случайный договор. Повтор externalId пропускается; отклонённые строки объясняются в UI.
- PARTIAL больше не исчезает из просрочки; остаток включает комиссию/НДС. Остаток основного долга в карточке следует фактическому приоритету распределения.
- Роль берётся из БД, неизвестная роль не получает права администратора. Открытый переключатель остаётся исключительно демонстрационным входом.
- Смена роли сохраняет путь. Удалены неработающие кнопки файлов и незавершённая доработка из основного сценария. Добавлены состояния загрузки/ошибки и подтверждение платежа. (Общий `app/loading.tsx` позднее удалён — причина в разделе «Сессия 2».)
- Комиссия калькулятора корректно подписана как сумма; исправлено повторное умножение IRR на 100 в карточке/калькуляторе.
- Фиксированная дата seed, учебный клиент, Z-DEMO-001 и ДЛ-DEMO-001. Синтетические контакты используют example.invalid и нерабочий телефон.
- db:setup корректно создаёт пустой SQLite-файл и не пересеивает существующую базу. Сброс явно подтверждается флагом. Seed запускается через node --import tsx.
- Серверные и браузерные тесты используют отдельные временные базы; пользовательская dev.db не затрагивается.

## Сессия 2 — 21.09.2026: закрытие блокеров

### Что исправлено

1. **Гонка навигации в `scripts/browser-smoke.mjs`.** `paymentUrl` записывался сразу после клика по ссылке ДЛ-DEMO-001 и содержал `/contracts`, из-за чего проверка DPD шла на списке договоров, а снимок `03-payments.png` делался не на карточке. Добавлен помощник `openCard(link, pattern, heading)`: он кликает, ждёт URL карточки, её заголовок и `networkidle`, и только потом возвращает адрес. Через него открываются досье клиента и карточка договора; адрес карточки дополнительно проверяется `assert`. По тому же принципу усилены остальные места: отправка заявки сверяет, что осталась на карточке; переход «Выбрать» → «Сформировать договор» ждёт параметр `?application=` и появление кнопки; возвраты на `paymentUrl` ждут заголовок `ДЛ-DEMO-001` и таблицу графика до снимка. Попутно исправлено имя параметра (`application`, не `applicationId`).

2. **React #418 и `Cannot read properties of null (reading 'parentNode')`.** Диагностика: production-сборка + Playwright, сравнение SSR-разметки с DOM после гидратации (совпадают), повтор с искусственно задержанными чанками и стресс-прогон из 30 переключений роли.
   - Расхождения содержимого нет: SSR и клиентский DOM отличались только атрибутом `disabled` у переключателя роли (снимается после гидратации) и служебным `next-route-announcer`.
   - Ошибки появлялись только на документах, загруженных перезагрузкой после действия, когда гидратация начиналась до окончания разбора потокового HTML (`document.readyState === "loading"`). Первой падала гидратация (#418), React перерисовывал корень клиентом, а приходившие следом встроенные скрипты `$RS` не находили свои `<div hidden>`/`<template>` — отсюда серия `parentNode`.
   - Источник потоковой отрисовки — `app/loading.tsx`: он создавал Suspense-границу, и каждая страница отдавалась как поток с `$RS`/`$RC`. Файл удалён. Замер: 30 переключений роли до удаления — 5 ошибок страницы, после удаления — 0, 0, 0 в трёх прогонах. Экран ошибки `app/error.tsx` сохранён; проверка `pageerror` в тесте не отключалась.
   - Проверялось и в dev-режиме: там ошибка не воспроизводится, поэтому диагностика велась на production-сборке.

3. **Обновление интерфейса после действий не менялось.** `lib/client-navigation.ts` (перезагрузка документа) и `components/action-feedback.tsx` (разовое уведомление) оставлены как есть — именно они дают согласованный экран после коммита транзакции. ### Ограничения

- Проверено только на Linux и Chromium. macOS, Safari, Windows и мобильная ширина не проверялись.
- В этой среде `npx playwright install chromium` не проходит (CDN недоступен), использовался уже установленный браузер через `CHROMIUM_PATH=/opt/pw-browsers/chromium npm run test:browser`. Абсолютный путь намеренно не прописан в коде проекта. На обычной машине достаточно `npx playwright install chromium`.
- Карточка договора: у графика 10 колонок, на ширине ~1440 px колонка «Статус» требует горизонтальной прокрутки таблицы. Это известное ограничение вёрстки, отмечено в сценарии показа.
- Без `app/loading.tsx` при медленной навигации пользователь видит предыдущую страницу до готовности новой. На локальных данных переходы занимают доли секунды.
- `npm run db:reset -- --confirm-demo-reset` в этой сессии **не выполнялся**: Prisma 6.19 определяет запуск из-под ИИ-агента и блокирует `migrate reset` до явного согласия пользователя (обходится переменной `PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION`). Для человека команда работает как раньше; ограничение относится к агенту, а не к скрипту. `npm run db:setup` проверен: на отсутствующей базе создаёт и засевает, при повторном запуске данные не перезаписывает. `npm start` отвечает 200 на `/`; `/contracts` без выбранной роли даёт 307 на главную — это ожидаемое поведение гостевого входа.
- Всё остальное из раздела «Ограничения и следующий шаг» выше остаётся в силе: реальные банк/AML/ЭЦП/DMS, полноценная аутентификация и изоляция данных, доработка заявки, нормативная корректность расчётов и промышленная нагрузка вне объёма.
