# HANDOFF — leasing-demo

## Цель и ветка

Довести до воспроизводимого локального демо три сценария: досье/заявка, согласование/договор, платёж/просрочка. Работа в `main`, исходный коммит `48d515e14b74f49a79ed56581594f2ce9ea79a0a`. Репозиторных AGENTS.md не найдено. Аудитория и срок пользователем не уточнены; рабочее допущение — один демонстратор, ноутбук/Chromium, 10–12 минут.

## Что изменено

- Последовательный маршрут: только первый шаг PENDING, последующие WAITING; запрет перескока, повторного решения и возобновления отклонённой заявки. Отправка и решение шага выполняются транзакционно.
- HARD действительно блокирует сделку; override только для сработавшего SOFT и с обоснованием; расширенный контроль требует устранения SOFT.
- Создаётся повестка новой заявки; три роли голосуют, большинство завершает заявку, повторный голос запрещён. Прямое согласование вместо голосования закрыто.
- Договор, график и предмет создаются одной транзакцией. Номера заявок/договоров получили случайный UUID-суффикс вместо диапазона из 900 значений.
- Оплаты учитывают частично погашенные компоненты; переплата/неверная сумма отклоняются; запись и распределение атомарны. Повтор запроса формы идемпотентен по requestId.
- CSV содержит точный договор/валюту; нет зачисления на случайный договор. Повтор externalId пропускается; отклонённые строки объясняются в UI.
- PARTIAL больше не исчезает из просрочки; остаток включает комиссию/НДС. Остаток основного долга в карточке следует фактическому приоритету распределения.
- Роль берётся из БД, неизвестная роль не получает права администратора. Открытый переключатель остаётся исключительно демонстрационным входом.
- Смена роли сохраняет путь. Удалены неработающие кнопки файлов и незавершённая доработка из основного сценария. Добавлены состояния загрузки/ошибки и подтверждение платежа.
- Комиссия калькулятора корректно подписана как сумма; исправлено повторное умножение IRR на 100 в карточке/калькуляторе.
- Фиксированная дата seed, учебный клиент, Z-DEMO-001 и ДЛ-DEMO-001. Синтетические контакты используют example.invalid и нерабочий телефон.
- db:setup корректно создаёт пустой SQLite-файл и не пересеивает существующую базу. Сброс явно подтверждается флагом. Seed запускается через node --import tsx.
- Серверные и браузерные тесты используют отдельные временные базы; пользовательская dev.db не затрагивается.

### Блокеры и конкретный следующий шаг

1. Исправить гонки навигации в `scripts/browser-smoke.mjs`. `paymentUrl` сейчас записывается сразу после клика ссылки ДЛ-DEMO-001 и может оказаться `/contracts`, до окончания перехода в карточку. В последнем прогоне это привело к ожиданию `Просрочка: DPD 61` на списке договоров. Явно дождаться URL карточки/её заголовка перед сохранением URL и снимком. Аналогично проверить все места, где скрипт кликает ссылку и сразу читает текущий URL или снимает экран. Не подменять действия в UI прямой записью в БД.
2. Разобраться с React hydration #418/parentNode: получить подробную ошибку в dev-режиме или trace, определить компонент/некорректную разметку либо гонку навигации. Не считать, что это только тестовая проблема, пока не проверено. До введения полного перехода страницы возникали также случаи «запись есть в БД, UI остался прежним». Не возвращать старый механизм без воспроизводимой проверки.
3. После исправления дождаться чистого завершения `npm run test:browser`: оплата → импорт → повтор импорта → +30 дней → DPD 61 → 14 страниц без pageerror/500. Визуально проверить снимки действительных карточек, а не загрузочного состояния. Сейчас снимок 03-payments мог быть сделан до окончания перехода.
4. Только после чистого прогона обновить статус готовности. Затем достаточно соразмерных проверок изменённых участков; не добавлять инфраструктуру/новые функции.

В текущем окружении скачивание Chromium с CDN не завершилось. Для прогона использовался браузер из npm-пакета @sparticuz/chromium, распакованный в scratch. Эти служебные файлы не являются зависимостями приложения и не коммитятся. Если они ещё доступны:

```bash
CHROMIUM_PATH=/workspace/scratch/9710ae73677d/browser-runtime/unpacked/chromium npm run test:browser
```

Не прописывать этот абсолютный путь в коде проекта. На обычной машине использовать Playwright install. Сервер браузерного теста и браузер запускаются одним процессом-оркестратором: отдельные exec в текущей среде могут иметь разные loopback-пространства.

Локальные диагностические файлы предыдущего прогона (могут исчезнуть): `/tmp/browser-ready.log`, `/tmp/build-ready.log`, `.demo-artifacts/01-application.png`, `02-contract.png`, `03-payments.png`, `failure.png`. У приложения нет секретов/внешних подключений. Все эти снимки и логи относятся к синтетической тестовой базе.
